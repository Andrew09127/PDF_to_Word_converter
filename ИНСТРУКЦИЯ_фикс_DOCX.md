# Инструкция: починить извлечение данных из Word (.docx) в sberAct

Задание для другого Claude. Доступа к исходному диалогу нет — здесь всё нужное.
Делается ТОЛЬКО фикс чтения DOCX. PDF/OCR не трогаем.

---

## 1. Суть проблемы (подтверждена разбором кода и экспериментом)

`sberAct` загружает Word и плохо извлекает данные. Причина — НЕ в парсинге полей,
а в том, что **текст теряется уже на этапе чтения DOCX**.

Метод `DocumentAnalyzer._extract_text_from_docx` в
`python-backend/app/document_analyzer.py` (~строка 1894) читает только:
- `doc.paragraphs` (тело);
- `doc.tables` → ячейки.

И НЕ читает:
- **колонтитулы** (шапка/бланк организации) — там обычно наименование, ИНН, ОГРН,
  адрес, банк;
- **текстовые поля / надписи / автофигуры** (`w:txbxContent`);
- **сноски / концевые сноски**.

В юридических заявлениях реквизиты часто лежат именно в колонтитуле или в надписи
на бланке. Этот текст не попадает в извлечённую строку → никакой regex или spaCy
его не найдёт, потому что его там просто нет.

Экспериментальное доказательство: в DOCX, где «ООО «АЛЬФА» ИНН 7707083893 ОГРН …»
лежит в колонтитуле, старый способ ИНН **теряет**, полный обход — **извлекает**.

Эталон полного обхода — `anonymizer/anonymizer/docx_processor.py`
(репозиторий https://github.com/Andrew09127/anonymizer_Word_files): методы
`_process_document_model` (колонтитулы всех секций) и `_process_raw_xml_parts`
(текстовые поля, сноски). Там это сделано для замены; нам нужно то же самое, но
для чтения/накопления текста.

---

## 2. Что сделать

Заменить тело `_extract_text_from_docx` на ПОЛНЫЙ обход, который собирает текст из:
1. тела (параграфы + таблицы) — **в порядке документа** (важно для контекстных
   паттернов sberAct вида «Должник:\nИП ...», на которых держится классификация);
2. текстовых полей/надписей (`w:txbxContent`) в теле;
3. колонтитулов всех секций (`first_page/header/even_page` и аналогичные footer),
   с дедупликацией (секции часто ссылаются на один колонтитул);
4. сносок и концевых сносок.

Ограничения:
- **Только офлайн**, без сетевых вызовов. Использовать `python-docx` + `lxml`
  (lxml уже идёт зависимостью python-docx). Новые пакеты не нужны.
- Сохранить контракт метода: на пустом результате кидать
  `ValueError("Документ пуст или не содержит извлекаемого текста")` — как сейчас.
- Не менять сигнатуру и формат ответа `analyze()` — фронтенд завязан на ключи
  словаря полей. Меняем только полноту входного текста.
- Комментарии — на русском (конвенция проекта).

## 3. Готовая реализация

В этой папке лежит проверенный drop-in модуль `docx_full_text.py` с функцией
`extract_text_from_docx(file_path) -> str` (тело + таблицы в порядке документа +
textbox + колонтитулы с дедупом + сноски; синтаксис и поведение проверены).

Перенести его в `python-backend/app/` и подключить:

```python
# в начале document_analyzer.py
from docx_full_text import extract_text_from_docx   # или относительный импорт под структуру app/

# заменить тело метода:
def _extract_text_from_docx(self, file_path: str) -> str:
    """Извлекает ВЕСЬ текст Word: тело, таблицы, колонтитулы, надписи, сноски."""
    return extract_text_from_docx(file_path)
```

(Согласовать стиль импорта со sberAct: там модули импортируются как топ-уровневые,
см. `main.py`: `from document_analyzer import DocumentAnalyzer`.)

## 4. Как проверить

1. **Синтаксис:**
   `python -c "import ast; ast.parse(open('document_analyzer.py',encoding='utf-8').read())"`
2. **Регрессия (раньше работавшие DOCX):** прогнать те же файлы через
   `POST /analyze-document` до и после; убедиться, что словарь `analyze()` не
   потерял прежние поля (новый обход — надмножество старого, поля должны только
   добавляться).
3. **Целевой кейс:** взять заявление, где реквизиты на бланке (в колонтитуле) или
   в надписи; убедиться, что ИНН/ОГРН/наименование теперь извлекаются и попадают
   в поля. Эталонный мини-тест: DOCX с «ИНН 7707083893» в колонтитуле — старый
   способ теряет, новый извлекает.
4. **End-to-end:** `POST /analyze-document` → `POST /generate-document` → открыть
   DOCX, проверить подстановки.
5. **Офлайн:** новых зависимостей нет; убедиться, что импортируются только
   python-docx и lxml.

## 5. На потом (НЕ в этой задаче)

Когда текст начнёт извлекаться полностью, второй слой улучшения — качество разбора
ФИО/реквизитов через детекторы из `anonymizer/anonymizer/detectors/` (Natasha NER +
regex с валидацией формата). Это отдельная задача поверх уже полного текста; сейчас
её не делаем.
